# ⚠️ 시스템 최적화 원칙 - 절대적 지침

> **이 원칙은 모든 제안과 답변에서 기본 숙지사항으로 반드시 적용해야 함!**

---

## 🎯 핵심 목표
**월 최소 1억원 순수익** (숏츠 폭발적 조회수 + 광고수익)

---

## 📋 절대적 원칙

### 1. 심플함 우선 (Simplicity First)
- n8n 노드 수는 **최소한**으로 유지
- 로직은 **직관적이고 가벼워야** 함
- 복잡한 분기보다 **단순한 흐름** 선호
- AS(유지보수) 로직이 무거워지면 안 됨

### 2. 플랫폼 최적화 (Platform Optimization)
- **쓸데없는 플랫폼 절대 없게!**
- 새 플랫폼 추가 전 반드시 질문:
  - "기존 플랫폼으로 해결 가능한가?"
  - "이게 정말 필수인가?"
  - "장기적 구독 비용은?"
- 현재 필수 플랫폼:
  - n8n (자동화)
  - PiAPI → Kling/Luma (영상 생성)
  - Typecast (TTS)
  - Creatomate (영상 합성)
  - YouTube API (업로드)

### 3. 비용 효율성 (Cost Efficiency)
- 초기 비용 **최대한 절감**
- 무료 = 이후 유료 전환 고려해야 함
- 플랫폼 하나 추가 = 월 구독료 + 유지보수 부담
- **ROI 없는 비용은 허용 안 됨**

### 4. 성능 우선 (Performance Priority)
- 단, 심플함이 성능을 해치면 안 됨
- **원활한 작동이 최우선**
- 조회수/광고수익에 직접 영향을 주는 부분은 투자 OK

---

## ⛔ 금지 사항

1. "일단 플랫폼 하나 더 추가하자" ❌
2. "노드 몇 개 더 넣으면 되지" ❌
3. "무료니까 괜찮아" (장기적 비용 미고려) ❌
4. 복잡한 에러 핸들링으로 로직 꼬이게 하기 ❌

---

## ✅ 권장 사항

1. 문제 발생 시 → 기존 플랫폼에서 해결책 먼저 찾기
2. 새 기능 추가 시 → 기존 노드에 통합 가능한지 검토
3. 복잡해지면 → 한 발 물러서 전체 구조 재설계 고려
4. 비용 발생 시 → "이게 월 수익에 어떤 기여를 하는가?" 질문

---

## 📊 현재 시스템 상태 체크

새 제안 전 항상 확인:
- [ ] 이 제안이 노드 수를 늘리는가?
- [ ] 새 플랫폼/구독이 필요한가?
- [ ] 기존 플랫폼으로 해결 가능한가?
- [ ] 장기적 유지보수 부담은?
- [ ] 월 수익 목표에 기여하는가?

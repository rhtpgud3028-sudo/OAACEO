# n8n 2.0 셀프호스팅 업그레이드 가이드

> **작성일**: 2026-01-26
> **현재 상태**: n8n 1.x (4버전 뒤쳐짐) → 최신: 2.6.0
> **중요도**: ⚠️ 메이저 업그레이드 (Breaking Changes 포함!)

---

## 📊 버전 분석

| 항목 | 현재 | 최신 | 상태 |
|------|------|------|------|
| **n8n 버전** | 1.x (추정) | **2.6.0** | 🔴 4버전 뒤쳐짐 |
| **업그레이드 유형** | - | 메이저 (1.x → 2.x) | ⚠️ Breaking Changes |
| **1.x 지원 종료** | - | 2.0 출시 후 3개월 | ⚠️ 빠른 대응 필요 |

---

## 🔴 Breaking Changes (중요!)

### 1. Execute Workflow 노드 동작 변경 ⚠️
**현재 워크플로우에 영향 가능성: 🟡 중간**

```diff
- 1.x: 서브 워크플로우가 독립 실행, 원본 입력 데이터를 메인으로 반환
+ 2.0: 서브 워크플로우에서 생성/수정된 데이터가 자동으로 메인으로 전달
```

**확인 필요**: Execute Workflow 노드 사용 여부 점검

---

### 2. Task Runners 변경 ⚠️
**현재 워크플로우에 영향 가능성: 🔴 높음 (Code 노드 사용 시)**

```yaml
# 2.0에서 필수 환경변수
N8N_RUNNERS_ENABLE=true
```

- `n8nio/n8n` Docker 이미지가 더 이상 외부 Task Runner로 사용 불가
- **Code 노드** 사용 중이므로 이 설정 필수!

---

### 3. 파일 접근 권한 변경 ⚠️
**현재 워크플로우에 영향 가능성: 🟢 낮음**

```yaml
# 파일 시스템 접근 필요 시
N8N_RESTRICT_FILE_ACCESS_TO=/allowed/path1,/allowed/path2
```

- 파일 경로에 `n8n-files` 접두사 필요할 수 있음

---

### 4. Workflow Publishing 방식 변경
**현재 워크플로우에 영향 가능성: 🟢 낮음 (UI 변경)**

- 기존: Activate 토글로 활성화/비활성화
- 2.0: 버전명으로 Publish (버전 관리 기능 추가)

---

### 5. 기타 제거된 기능
| 제거 항목 | 대체 방법 |
|----------|----------|
| `--tunnel` 플래그 | Cloudflare Tunnel 등 사용 |
| `--file` 플래그 (CLI) | workflow import 후 `--id`로 실행 |
| SQLite Legacy Driver | 최신 드라이버로 전환 |

---

## ✅ AIASF 워크플로우 영향도 분석

| 노드/기능 | 사용 여부 | 영향도 | 대응 |
|----------|----------|--------|------|
| **Code 노드** | ✅ 사용 (Shotstack Builder 등) | 🔴 높음 | `N8N_RUNNERS_ENABLE=true` 설정 필수 |
| **HTTP Request 노드** | ✅ 사용 | 🟢 낮음 | 변경 없음 |
| **Execute Workflow** | ❓ 확인 필요 | 🟡 중간 | 서브워크플로우 사용 시 검토 |
| **파일 시스템 접근** | ❓ 확인 필요 | 🟡 중간 | BGM/Video 파일 경로 점검 |

## 🛠️ 업그레이드 절차 (SSH로 서버 접속)

### 1단계: 백업 (필수!)
```bash
# SSH 접속
ssh -i ~/.ssh/id_rsa root@38.60.220.9

# n8n 데이터 백업
cd /opt/n8n
docker compose down
tar -czvf n8n_backup_$(date +%Y%m%d_%H%M%S).tar.gz ./data
```

### 2단계: 워크플로우 내보내기
- n8n UI에서 **모든 워크플로우** JSON 내보내기
- 로컬에 백업 저장

### 3단계: Migration Report 확인 (권장)
⚠️ **n8n 1.121.0 이상**에서만 사용 가능

1. n8n UI → Settings → Migration Report
2. 워크플로우별/인스턴스별 이슈 확인
3. 문제 항목 기록 및 사전 수정

### 4단계: 환경변수 추가
```bash
# docker-compose.yml 또는 .env 파일에 추가
nano docker-compose.yml
```

```yaml
environment:
  # ... 기존 설정 ...
  - N8N_RUNNERS_ENABLE=true  # Code 노드용 (필수!)
```

### 5단계: Docker 이미지 업그레이드
```bash
# docker-compose.yml에서 이미지 태그 수정
# n8nio/n8n:1.x.x → n8nio/n8n:2.6.0

# 또는 latest 사용 (권장하지 않음)
# n8nio/n8n:latest
```

```bash
# 업그레이드 실행
docker compose pull
docker compose down
docker compose up -d

# 로그 확인
docker compose logs -f
```

### 6단계: 업그레이드 후 검증
```bash
# n8n 버전 확인
docker exec -it n8n n8n --version

# 웹 UI 접속 후 확인:
# 1. 모든 워크플로우 활성화 확인
# 2. Code 노드 정상 동작 확인
# 3. HTTP Request 노드 정상 동작 확인
```

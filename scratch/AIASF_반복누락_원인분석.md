# 🔴 반복 누락 원인 분석 및 영구 해결책

> **작성일**: 2026-01-12
> **문제**: 백업/PM2 자동 재시작 확인 항목이 매일 작업 요약에서 누락됨
> **목적**: 근본 원인 분석 및 재발 방지 대책 수립

---

## 📊 1. 문제 현상

| 누락 항목 | 빈도 | 영향 |
|----------|------|------|
| n8n 백업 확인 | **매일** | 데이터 손실 위험 |
| PM2 자동 재시작 확인 | **매일** | 서비스 중단 위험 |
| 크론잡 확인 | **매일** | 스케줄 실패 위험 |

---

## 🔍 2. 근본 원인 분석 (5 Whys)

### Why 1: 왜 누락되는가?
→ 작업 요약 시 "신규 작업"에만 집중하고 "운영 점검" 항목을 빠뜨림

### Why 2: 왜 신규 작업에만 집중하는가?
→ 대화 컨텍스트가 잘리면 이전 세션의 "필수 점검" 지침이 사라짐

### Why 3: 왜 컨텍스트가 잘리면 잊는가?
→ **영구 체크리스트 파일이 없음** - 매번 메모리에만 의존

### Why 4: 왜 영구 체크리스트가 없는가?
→ 시스템적 해결책 없이 수동 기억에 의존했음

### Why 5: 근본 원인
→ **표준 운영 절차(SOP) 부재** + **자동 체크 메커니즘 없음**

---

## 🎯 3. 근본 원인 정리

| 원인 | 유형 | 심각도 |
|------|------|--------|
| **영구 체크리스트 부재** | 시스템적 | 🔴 Critical |
| 컨텍스트 잘림 시 정보 손실 | 기술적 | 🟠 High |
| 신규 작업 편향 | 행동적 | 🟡 Medium |

---

## ✅ 4. 영구 해결책

### 해결책 A: 필수 점검 체크리스트 파일 생성

**파일**: `.agent/workflows/daily-check.md`

```markdown
---
description: 매일 작업 종료 시 필수 확인 사항
---

## 🔴 필수 확인 (매일!)

// turbo-all

1. SSH 접속
2. `pm2 status` - n8n 실행 상태 확인
3. `crontab -l` - 백업 크론잡 확인
4. `ls -la /var/www/html/backups/` - 백업 파일 존재 확인
5. n8n 웹 접속 테스트 - https://autoshort.site

## 결과 보고
- PM2 상태: [online/stopped]
- 크론잡 설정: [확인됨/없음]
- 최근 백업: [날짜]
- n8n 접속: [성공/실패]
```

### 해결책 B: 작업 요약 템플릿에 필수 포함

모든 작업 요약 문서에 아래 섹션 **필수 포함**:

```markdown
## ⚠️ 필수 확인 (작업 종료 전!)

| 항목 | 확인 명령어 | 상태 |
|------|-----------|------|
| PM2 상태 | `pm2 status` | ✅/❌ |
| 백업 크론잡 | `crontab -l` | ✅/❌ |
| n8n 접속 | 브라우저 테스트 | ✅/❌ |
```

### 해결책 C: 강제 리마인더 메커니즘

**작업 종료 시 반드시**:
1. `daily-check.md` 워크플로우 실행
2. 결과를 작업 요약에 기록
3. 미확인 시 작업 종료 불가

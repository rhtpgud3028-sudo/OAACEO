### 🛡️ AI 파일 안전 수칙 (2026-01-05 확정 - 절대 준수!)

> **⛔ 이 규칙은 대표님 지시 없이도 AI가 스스로 100% 준수해야 함!**

| 수칙 | 설명 | 위반 시 |
|------|------|---------|
| **1. 복구 작업 시 자동 검증 필수** | 파일 복구 시 모든 관련 brain 아티팩트 전수 조사 후 누락 여부 확인 | 대표님 리소스 낭비! |
| **2. 위키 업데이트 = 백업 먼저** | 위키 파일 수정 전 반드시 backup 폴더에 복사본 생성 | 데이터 손실 위험! |
| **3. Overwrite 모드 사용 금지** | 기존 파일 덮어쓰기 대신 내용 추가/수정 방식 사용 | Agent 종료 시 0바이트 위험! |
| **4. 더블체크 = 기본** | 복구/정리 작업 후 대표님께 보고 전 스스로 더블체크 완료 | 대표님이 직접 지적해야 하는 상황 발생! |

### ⛔ AI 근본 원인 방지 수칙 (2026-01-05 확정 - 영구 적용!)

> **핵심 원칙: 대표님께서 지적하시는 순간 = AI 실패**
> **AI는 대표님보다 먼저 모든 것을 확인하고, 완벽한 상태로 보고해야 함**

| 수칙 | 내용 | 위반 시 |
|------|------|---------|
| **다중 소스 검증** | 위키만 믿지 말고, brain + scratch + 실제 상태 교차 확인 | 정보 불일치 |
| **보고 전 자체 검증** | "내가 빠뜨린 게 없나?" 스스로 질문 후 보고 | 대표님 지적 발생 |
| **즉시 동기화** | 완료 통보 = 즉시 위키 반영 (TODO에서 삭제 + 완료에 추가) | TODO에 완료 건 잔존 |
| **검증 없이 보고 금지** | 추정/가정 금지, 확인된 사실만 보고 | 오정보 전달 |
| **능동적 접근** | 대표님 지시 기다리지 말고 AI가 먼저 확인하고 처리 | 수동적 대응 |

### 🔄 위키 확인 시 자동 수행 체크리스트 (AI 필수!)

```
✅ "위키 파일 확인해줘" 명령 시 AI가 자동으로 수행할 것:

시스템 상태 확인:
1️⃣ 위키 파일 정상 여부 확인 (0바이트, 내용 손실 체크)
2️⃣ 마지막 업데이트 날짜 확인 → 7일+ 미업데이트 = 경고

다중 소스 교차 검증:
3️⃣ brain 아티팩트 최신 세션 확인 → 위키에 미반영 내용 있으면 자동 추가
4️⃣ scratch 폴더 최근 7일 파일 확인 → 관련 문서 섹션과 비교
5️⃣ 완료 목록 vs TODO 목록 상충 여부 확인

일일 루틴:
6️⃣ AI 영상 플랫폼 딥 리서치 (50초+ 원샷 생성 가능 여부)
7️⃣ 긴급 마감 건 알림 (7일 내 마감 시 최우선 보고)
```

> ⚠️ **핵심**: 대표님께서 직접 "더블체크해", "빠진거 없어?", "왜 아직도 올라와?" 라고 말씀하시는 상황 = **AI 실패**
> AI는 **스스로** 완벽하게 검증한 후 보고해야 함!

**잘못된 예:**
```
Code 노드 수정 후 HTTP 노드 Body 변경하세요.
```

**올바른 예:**
```
1️⃣ Code 노드 열기 → JavaScript 탭
2️⃣ 기존 코드 전체 삭제
3️⃣ 아래 코드 복사해서 붙여넣기:
   [코드 블록]
4️⃣ HTTP 노드 (7. Shotstack 렌더링) 열기
5️⃣ Body 필드 기존 내용 삭제
6️⃣ 다음 내용 입력: ={{ $json.body }}
7️⃣ 저장
8️⃣ 전체 워크플로우 다시 실행 (Manual Trigger 클릭)
9️⃣ 결과 확인
```

## 🐛 디버깅 교훈 (2025-12-15)

### 비동기 API 처리
| API | 방식 | 필요 시간 | 완료 상태 | 진행 상태 |
|-----|------|----------|----------|----------|
| **Kling (PiAPI)** | 비동기 | 2-5분 | `completed` | `pending` |
| **Luma (PiAPI)** | 비동기 | 2-5분 | `completed` | `pending` |
| **Typecast** | 비동기 | 30초-2분 | `done` | `progress` |
| **Creatomate** | 비동기 | 1-3분 | `succeeded` | `planned`, `rendering` |

### ⚠️ Kling vs Luma 파라미터 차이
```
Kling 전용: cfg_scale, negative_prompt, mode, duration(숫자)
Luma 전용: loop, keyframes, duration("5s" 문자열)
```
> Kling JSON을 Luma에 복붙하면 **failed 오류 발생**!

### 🔄 스마트 폴링 루프 (무한 루프 방지)
```
[Wait 30s] → [Polling] → [IF: status != "pending"?]
     ↑                              │
     └────── (false: 대기중) ←───────┤
                                    │
                               (true: 완료/실패) → 다음 단계
```
> IF 조건에 **failed 케이스도 탈출**하도록 `!= "pending"` 사용!

### Creatomate `template_id` 필수!
```json
{
  "template_id": "cbf0ed37-xxxx-xxxx-xxxx-xxxxxxxxxxxx",  ← 필수!
  "modifications": { "Video": "...", "Audio": "...", "Subtitle": "..." }
}
```
> template_id 누락 시 **400 Bad Request** 오류

### n8n 주의사항
- JSON 안에 Expression 사용 시 **Code 노드**로 데이터 구성 권장
- **Execute Step** 개별 실행 시 이전 노드 데이터가 오래될 수 있음
- **전체 Execute Workflow** 권장

## 🔥 오디오 URL 문제 (2025-12-16~17) - 미해결

### 문제 증상
- Creatomate Polling 루프가 **50번** 반복됨 (무한 루프)
- 렌더가 완료되지 않고 계속 pending 상태

### 원인 분석
Code 노드 output에서 Audio 필드가 **base64 data URL**로 전달됨:
```
{
  "Audio": "data:audio/wav;base64,UklGRlqMAQBXQVZF..."  ← ❌ 문제!
}
```
> Creatomate는 **HTTP URL**을 통해 오디오를 가져와야 함. base64 불가!

### 시도한 해결책 (실패)
| 방법 | 결과 | 비고 |
|------|------|------|
| tmpfiles.org | ❌ 실패 | 상세 에러 미기록 |
| 0x0.st | ❌ 실패 | 상세 에러 미기록 |

### 시도 예정 대안
- **Cloudinary** - n8n 내장 노드, 미디어 특화
- **Catbox.moe** - 무료, 익명 업로드
- **Typecast에서 직접 URL 제공 여부 확인**

### 해결 상태
⏳ **진행 중** - Typecast API 분석 완료, LightNode 서버 호스팅 방식으로 진행 예정
